# AWS plugin

Gives agent containers read-only AWS access through AWS CLI profiles. It has no exec tools.
A startup hook writes `~/.aws/config` with a base profile and one role profile per
configured account, so the `aws` CLI and SDKs assume those roles. The base profile gets the
stored credentials from `bin/credential-process` on every use, so a new host login reaches
running sessions without a restart.

## Namespaces and functions

No namespaces and no tools. The model learns how to use the generated profiles (list them,
pass `--profile`, handle `AccessDenied` and expired credentials) from
`skills/aws-agent-access/SKILL.md`.

## Credential

Static, fields `access_key_id`, `secret_access_key` and `session_token` (`login: aws_chain`).
`archie auth login aws` resolves credentials from the standard boto3 chain on the host,
validates them with STS `GetCallerIdentity`, and stores them. Use short-lived credentials,
for example:

```bash
aws-vault exec <profile> -- archie auth login aws
```

`set_env: false`: the credentials are not exported into containers. These are the base
identity, which should only be able to assume the configured roles. This entry is separate
from `bedrock`, which the model provider uses. When the session token expires, run the login
again on the host; running sessions use the new credentials at their next role renewal (see
[How it works](#how-it-works)). The `env` mapping applies only if a user override sets
`plugins.aws.auth.set_env: true`, which exports the base credentials into shell commands; profile calls ignore them.

## Configuration

```yaml
plugins:
  aws:
    enabled: true
    settings:
      region: eu-west-1          # default
      profiles:                  # profile name -> role ARN; default none
        agent-staging: arn:aws:iam::111111111111:role/agent-access
        agent-production: arn:aws:iam::222222222222:role/agent-access
```

| Key | Type | Default | Read | Meaning |
| --- | --- | --- | --- | --- |
| `settings.region` | str | `eu-west-1` | startup | `region` written into every profile |
| `settings.profiles` | dict[str,str] | none | startup | Profile name → role ARN |

No tool policy (no tools). `enabled: false` stops the credential being projected, hides
login, and skips the startup hook and the skill.

## How it works

`profiles.py` holds the startup hook `write_config()` (manifest `hooks.startup`). It runs
once when the agent starts, reads `settings` from `context()` and never reads credentials.

- No `profiles` (missing or empty): it does nothing; an existing `~/.aws/config` is left alone.
- Otherwise it renders, under the header line `# Generated by Archie from
  plugins.aws.settings.profiles; changes are overwritten.`:
  - a base profile `[profile archie-base]` with `region` and
    `credential_process = <plugin dir>/bin/credential-process`;
  - one section per configured profile, sorted by name: `[profile <name>]`, `region`,
    `role_arn`, `source_profile = archie-base`.

  The file holds no secrets.
- Profile names must match `[A-Za-z0-9][A-Za-z0-9_-]*` and must not be `archie-base`; region
  and ARNs must be non-empty single lines (no INI injection). Validation happens before any
  file is touched.
- It refuses (`AwsProfilesError`, which stops the agent) when `~/.aws` or `~/.aws/config` is a
  mount point, or when an existing `~/.aws/config` does not start with the generated header.
  So `~/.aws` must not be mounted into the container when `profiles` is set.
- It writes atomically (temp file + rename), with the directory `0700` and the file `0600`.

`bin/credential-process` (bash, needs `yq`, `jq` and `date`) reads `aws.access_key_id`,
`aws.secret_access_key` and `aws.session_token` from `$ARCHIE_HOME_DIR/credentials.yaml` on
every run and prints them as `credential_process` JSON. It exits 1 with a message naming
`archie auth login aws` when the store or the fields are missing. Because the store does not
record when the session token expires, it reports an `Expiration` 20 minutes ahead. AWS
clients refresh credentials 15 minutes before `Expiration`, so a long-running SDK session
runs the helper again about every 5 minutes. Role credentials, cached by the CLI under
`~/.aws/cli/cache` or held by an SDK session, are reused until about 15 minutes before they
expire, so a new login takes effect at the next role renewal. See
[AWS credential refresh](../../docs/auth-credentials.md#aws-credential-refresh).

## Tests

`plugins/aws/tests/test_aws_profiles.py` covers rendering, validation, permissions, atomic
replace, the refusal rules and that credentials are never read; it uses fixtures in that file
(`home`, `use_settings`) built on `make_plugin_context`.
`plugins/aws/tests/test_aws_credential_process.py` runs `bin/credential-process` as a
subprocess against a temporary store (output format, per-call reads, failures) and, when the
AWS CLI is installed, checks that `aws configure export-credentials` resolves the generated
base profile through it. Run `uv run pytest -q plugins/aws`.

See [docs/plugins.md](../../docs/plugins.md) for the manifest format, the plugin SDK and testing conventions.
