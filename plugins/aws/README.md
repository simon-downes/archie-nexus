# AWS plugin

Gives agent containers read-only AWS access through AWS CLI profiles. It has no exec tools:
the host projects temporary base credentials into the container environment, and a startup
hook writes `~/.aws/config` with one role profile per configured account, so the `aws` CLI
and SDKs assume those roles.

## Namespaces and functions

No namespaces and no tools. The model learns how to use the generated profiles (list them,
pass `--profile`, handle `AccessDenied` and expired credentials) from
`skills/aws-agent-access/SKILL.md`.

## Credential

Static, fields `access_key_id`, `secret_access_key` and `session_token` (`login: aws_chain`).
`archie auth login aws` resolves credentials from the standard boto3 chain on the host,
validates them with STS `GetCallerIdentity`, and stores them. Use short-lived credentials,
for example:

```bash
aws-vault exec <profile> -- archie auth login aws
```

`set_env: true`: new containers get `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and
`AWS_SESSION_TOKEN`. These are the base identity, which should only be able to assume the
configured roles. This entry is separate from `bedrock`, which the model provider uses and
which is never projected. When the session token expires, log in again and start a new
session.

## Configuration

```yaml
plugins:
  aws:
    enabled: true
    settings:
      region: eu-west-1          # default
      profiles:                  # profile name -> role ARN; default none
        agent-staging: arn:aws:iam::111111111111:role/agent-access
        agent-production: arn:aws:iam::222222222222:role/agent-access
```

| Key | Type | Default | Read | Meaning |
| --- | --- | --- | --- | --- |
| `settings.region` | str | `eu-west-1` | startup | `region` written into every profile |
| `settings.profiles` | dict[str,str] | none | startup | Profile name → role ARN |

No tool policy (no tools). `enabled: false` stops the credential being projected, hides
login, and skips the startup hook and the skill.

## How it works

`profiles.py` holds the startup hook `write_config()` (manifest `hooks.startup`). It runs
once when the agent starts, reads `settings` from `context()` and never reads credentials.

- No `profiles` (missing or empty): it does nothing; an existing `~/.aws/config` is left alone.
- Otherwise it renders one section per profile, sorted by name:
  `[profile <name>]`, `region`, `role_arn`, `credential_source = Environment`, under the
  header line `# Generated by Archie from plugins.aws.settings.profiles; changes are
  overwritten.` The file holds no secrets.
- Profile names must match `[A-Za-z0-9][A-Za-z0-9_-]*`; region and ARNs must be non-empty
  single lines (no INI injection). Validation happens before any file is touched.
- It refuses (`AwsProfilesError`, which stops the agent) when `~/.aws` or `~/.aws/config` is a
  mount point, or when an existing `~/.aws/config` does not start with the generated header.
  So `~/.aws` must not be mounted into the container when `profiles` is set.
- It writes atomically (temp file + rename), with the directory `0700` and the file `0600`.

## Tests

`plugins/aws/tests/test_aws_profiles.py` covers rendering, validation, permissions, atomic
replace, the refusal rules and that credentials are never read; it uses fixtures in that file
(`home`, `use_settings`) built on `make_plugin_context`. Run `uv run pytest -q plugins/aws`.

See [docs/plugins.md](../../docs/plugins.md) for the manifest format, the plugin SDK and testing conventions.
