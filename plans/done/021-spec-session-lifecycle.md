# 021 — SPEC: Session lifecycle through the orchestrator (`start` + `stop`)

## Objective

Move container lifecycle (create and destroy) behind the orchestrator API.
`POST /sessions` accepts a workspace name, starts a container, waits for ready, and
returns the session descriptor. `DELETE /sessions/{id}` stops a container. The CLI's
`start` and `stop` commands become pure API calls.

## Context

This is M2a of project plan 019 (Orchestrator Control Plane). After M1 (020-spec), the
orchestrator exists and serves `GET /sessions`. This slice adds the write path. Together
with M2b (attach/shell), this removes all direct Docker calls from `cli.py`. The
orchestrator becomes the single owner of container lifecycle.

Locked decisions inherited: D1 (control plane only), D3 (co-located sessions,
host-path mounts), D4 (decoupled lifecycle), D6 (`archie serve`),
D7 (`--add-host` stays; backend addr is per-model catalog data).

Depends on: 020-spec-serve-and-ls (M1 must be implemented first).

## Technical Design

### API Endpoints

**`POST /sessions`**
```
Request:  {"workspace": "<name>"}
Response: SessionDescriptor (JSON, msgspec-encoded)
          HTTP 200 on success
          HTTP 400 on bad workspace (doesn't exist)
          HTTP 500 on Docker/startup failure (with error detail)
```

**`DELETE /sessions/{session_id}`**
```
Response: HTTP 200 + {"stopped": "<session_id>"} on success
          HTTP 404 if no running session with that exact ID
```

### 2. Implement session start logic in the orchestrator (`lifecycle.py`)

**Approach:**
- Create `orchestrator/src/archie_orchestrator/lifecycle.py` with `start_session()`.
- Validate workspace exists under `expand_workspace_root(config)`.
- Check image exists via `check_image()`.
- Generate session ID via `generate_session_id(workspace=name)`.
- Ensure `~/.nexus` and `~/.agents` dirs exist (create if missing).
- Construct full `docker run` command (same mounts/env/options as cli.py:252–286).
- Derive `REPO_ROOT` from `Path(__file__).resolve().parents[3]`.
- Execute via `run_container()`.
- Wait for ready via `wait_for_ready()` (polls container liveness, port publication,
  and `/status` 200 using `urllib.request`).
- Return `SessionDescriptor`.
- Extend `docker.py` with: `run_container()`, `stop_container()`, `check_image()`,
  `wait_for_ready()`, `_container_running()`, `_status_ok()`.
- Test seam: mock `subprocess.run` for Docker commands; mock
  `urllib.request.urlopen` for `/status` polling.

**Wiring:**
- State: no persistent state; session info is transient (rediscoverable from Docker)
- Producers: `start_session` creates a container via subprocess
- Consumers: route handler in app.py (milestone 4)
- Call site: `descriptor = await asyncio.to_thread(start_session, workspace, config)`

**Edge cases:**
- Workspace doesn't exist: raise `ValueError` (route returns 400)
- Image not found: raise before attempting `docker run`, clear message
- Container crashes during startup: `_container_running` returns False, raise with
  debug guidance (show command to re-run without `--rm`)
- Docker daemon unreachable: subprocess returns non-zero, raise with message
- Port not assigned / timeout: `wait_for_ready` exceeds 30s, raise

**Tasks:**
- Create `orchestrator/src/archie_orchestrator/lifecycle.py`
- Implement `start_session(workspace, config) -> SessionDescriptor`
- Extend `orchestrator/src/archie_orchestrator/docker.py` with `run_container()`,
  `check_image()`, `wait_for_ready()`, `_container_running()`, `_status_ok()`
- Create `tests/test_orchestrator_lifecycle.py`
- Test: correct `docker run` command constructed for given workspace + config
- Test: workspace not found → `ValueError`
- Test: image not found → error before docker run
- Test: `wait_for_ready` succeeds after N polls (mock urllib + subprocess)
